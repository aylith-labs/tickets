In the browser

The local daemon serves a UI for all registered projects, or one project at a time. Create, edit, and review tickets without turning your working notes into another cloud account.

In the terminal

Use the separate Tickets TUI to browse projects and tickets alongside your code. The CLI registers projects, lists them, and manages storage.

In your repository

Tickets are Markdown files. Start with a folder, or choose a dedicated Git worktree for commit-backed history and synchronization.

From your project folder

The example uses your Downloads folder. If you saved the file elsewhere, replace that path. Run these commands from the repository you want to track, using plain-folder storage:

chmod +x "$HOME/Downloads/tickets-linux-x64"
"$HOME/Downloads/tickets-linux-x64" init --adapter folder
"$HOME/Downloads/tickets-linux-x64" serve

Open the local URL printed by the daemon. Create your first ticket, add the context, then copy its agent prompt from the ticket menu.

Tickets is a local, authentication-free daemon. Keep it on a trusted machine; this website does not host your tickets.

Storage and installation details

The default Git-backed setup needs Git 2.42 or later and creates a separate tickets worktree. Use tickets init to choose it. Folder storage avoids that worktree requirement, but does not provide Git-backed history or synchronization.

The standalone download above is the simplest way to get the browser app. The release notes describe the version you download.

macOS may require you to approve an unsigned downloaded executable before running it. Read the installation guide for your platform.
